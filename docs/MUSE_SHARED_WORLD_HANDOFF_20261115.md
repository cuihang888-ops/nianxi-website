## 先读这个

安和里是一片可以长期生活、看见邻居的德宏原野。很多真实玩家各自创建人物，在喜欢的地方安家，以游戏内安币买地、养动物、种植、出售产物，再步行或骑马去瑞丽总佛寺静坐、祈福、挂红结。别人下线后，家和田地仍在；回来能接着生活。

参考“网上南宁”的是可辨认的地方、人物在世界中活动、公共空间与多人共同在场的产品类型。视频中预告的多人模式尚未由本项目实际试玩核验，不能把宣传内容当作服务器或性能依据。安和里保持自己的德宏自然环境、原野交通和治愈节奏。

当前免费、不充值、不提现、不接商城支付。“赚钱”只指游戏内安币。动物不因缺席死亡，离线不收地，不做地皮炒卖、战力排名、断签惩罚或付费祈福。寺院仪式不增加生产收益，不承诺现实好运。

## 地图应该大在哪里

世界使用德宏五区的稳定 ID：`ruili`、`mangshi`、`longchuan`、`yingjiang`、`lianghe`。这是游戏化地理，不是现实土地交易、准确测绘或古代德宏复原；瑞丽总佛寺是共同的精神与社交中心，尚无寺院官方合作或准确建筑复刻。

地图分四层：

| 层次 | 玩家体验 | 实现职责 |
| --- | --- | --- |
| 世界总览 | 看五区、自己家、好友所在区域与路线 | 稳定区域/路线目录，区域加载 |
| 坝区 | 可辨认的山、水、田、树林、集市、村路和山林入口 | 分块地形、碰撞、道路与地标 |
| 共享村落 | 沿村路看见真实邻居的房屋、农田和动物 | 持久村落、地块目录、邻近订阅 |
| 自己的地块 | 建家、种养、装饰、日常照料 | 地块边界、经营锚点、归属权限 |

先把瑞丽的一片河谷村落与总佛寺通路做好：出生歇脚处、相邻地块、井边或榕树下、系统集市、步行/骑马道路、寺院和红结树。先形成有内容的连续生活路线，再以同一契约扩展五区，避免只扩大平地。

每个村落有固定公共道路与地块，不允许玩家圈住路、寺院入口或其他人的房子。村落满了由服务端扩展同地区新村落，并提供访友定位；不制造“全服只有少量地皮”的压力。既有村落及住址保持稳定，不重新随机分配老玩家。

共享地权不随在线频道改变。同一村落可有多个在线频道，房屋和地块投影一致；好友可会合到有容量的同一频道。人数满时提示真实情况，不伪造同屏在线人数，也不承诺全服几千人同时在一台手机上绘制。

小地图至少显示自身朝向、村路/桥、家、系统集市、寺院、目的地和区域出口；只有真实已同步玩家才显示邻居在线标记。支持选目的地、取消路线、返回自己家位置。路径不可达、未加载和断网要有明确反馈；地图定位不直接传送。

## 一人一角色与持久家园

服务端登录后确定唯一 `playerId`，外观、昵称和家名是角色资料，换设备仍是同一个人。首轮用有限的服饰/发型/颜色选项，避免先投入复杂捏脸编辑器；不能用昵称当唯一身份。昵称等用户输入按平台要求校验，首轮公共愿文使用固定选项。

新世界标识统一为：

| 字段 | 含义与不变量 |
| --- | --- |
| `worldId` | 同一持久世界；不随登录重新生成 |
| `regionId` | 已有五区 ID，保留不改名 |
| `settlementId` | 已有聚落样式目录，兼容旧选址资料 |
| `villageId` | 该地区中一个持久村落，不等同于临时频道 |
| `plotId` | 全局唯一的游戏地块，归属以服务端为准 |
| `homeId` | 玩家的家园资产，迁居不重发余额、动物或物品 |
| `instanceId` | 临时在线频道；不拥有地权 |
| `chunkId` | 地形/邻近数据订阅分块，与地权分离 |
| `playerId` / `assetId` | 稳定玩家与资产 ID，不由画面临时生成 |

买地流程：查看可用地块和配置价格 → 确认 → 服务端在一次事务内检查地权与余额、扣币、登记归属、写回执 → 确认后展示自己的家。首轮一个主家园，额外可经营地块数由配置控制，不能用无限购买堵住村路。

两人同时买一块地，只能一人成功，失败者不扣币。网络超时重试使用同一 `idempotencyKey`；先查询或返回原回执，不再扣一次。客户端不得乐观展示“买地成功”后才尝试保存。

下线只移除在线人物，房屋、田地、动物及红结继续保存。长期离线不失去家园；离线产出上限沿用配置，结算以服务端时间为准。首轮经营只能由主人操作；访客可观察与做无经济影响的友好动作，不能拿走收获、卖动物或修改布局。

## 经营与安币

维持现有免费版手感。小游戏数值以 `wechat/vendor/preview-economy.cjs` 为准，原网页农场的 `src/economy-config.js` 是另一路规则；不能用旧模拟报告参数整体替换。

首轮沿用已有买地、动物、种子、建屋、马匹与系统回购数值。新世界首块地是否另给免费券，需单独配置与一次性领取记录，不因“免费试玩”自动把地价改成零。新增共享地块目录的面积和经营容量需要与 Muse 的实际布局对齐。

`买地/购买动物/种植/浇水/喂养/收获/卖货` 是服务端命令，客户端只提交意图、实体 ID、预期版本和幂等键。服务端检查主人、库存、价格、容量、时间及次数，原子提交钱包、资产和回执；不能上传整份本机 JSON 覆盖权威资产。

不做玩家自由转账、地块转售或现金提现。当前“集市”仍是系统固定价格回购；玩家交易另行立项。狩猎如纳入新世界，结果及次数由服务端判定，不接受客户端传入“成功=true”直接发钱。

账本使用整数最小单位。建议 `100 coinMinor = 1 安币`，兼容试玩中已有 `0.5 安币`，迁移必须精确换算并测试，不能取整改变余额。正式常规交通是步行/骑马；现有试玩回家/水晶快捷入口另行收敛，本文不直接更改它们。

保留未来经济配置版本和按来源/去向的观测：登录、在线、经营、狩猎、活动入账，买地、动物、种子、建屋、马匹消耗，以及余额快照、登录和停留。首轮不采用 NPC 每日 80 安币上限、45 天动物退休、收费月卡或充值重调。新增祈福和挂红结不额外发币、不提高产量；现有静心完成小确幸及领取 40 安币的流程沿用现行配置，奖励仍走原活动命令。

## 寺院与红结

瑞丽总佛寺既能独处，也能和真实朋友同时到达。保留静坐、木鱼、念珠、礼拜、饮茶等体验，新增树上/架上红结锚点。马匹在寺院外停留，人物步行入院，不能因到寺院而扣钱或要求完成经营任务。

祈福分为动作与记录：礼拜/合掌是临时人物状态；红结是持久记录，使用 `knotId, ownerId, templeId, anchorId, wishPreset, createdAt, revision`。复用总佛寺 ID `ruili-temple`。首轮固定祝愿如平安、家人、健康、学业、感谢，不接受自由文本，不与收益倍率绑定。

服务端确认玩家在合法交互范围、锚点存在、频率与可见数量符合配置后保存红结，再同步给附近玩家。重试不重复创建。红结归属持久世界和寺院，不归属在线频道；同寺不同频道读取相同记录，频道仅影响在线人物和临时动作。树上只绘制有限数量的近期红结，自己的完整记录分页保留；视觉层轮换不删除长期记录。公开投影不包含登录凭据、平台 openid 或私人经济明细。

旧版心灯两分钟消失、服务重启即清空，不能直接改个名字充当持久红结。祈福免费；不做功德榜、付费愿力、好运概率或跨寺院收入比较。

## Codex 要交付的服务契约

以下是 v2 设计，不复用旧匿名 `/ws` 的身份票据，也没有线上地址。微信登录会话用于换取短期、限定世界的连接票据；票据不放 URL 或日志，匿名来客不能取得地权。

| 接口/能力 | 输入 | 服务端结果 |
| --- | --- | --- |
| 世界引导 | 已验证账号 | `playerId`、角色、家园、世界目录和配置版本 |
| `GET /v2/world/plots` | `worldId, villageId` | 地块边界、当前归属公开投影、价格及版本 |
| `POST /v2/world/commands` | `commandId, kind, targetId, expectedRevision, configVersion, payload` | 权威状态变化与可重试回执；`commandId` 作为玩家域内幂等键 |
| `GET /v2/world/receipts/:commandId` | 自己的命令 ID | 成功、拒绝或尚未提交；查不到不等于可以重新生成命令扣币 |
| 世界连接票据 | 已验证会话、`worldId` | 短期单次票据与过期时间 |
| v2 世界订阅 | 票据、区域/村落/分块 | 初始快照、快照基准序号、按序增量、服务端时间和真实在线数 |
| 红结记录 | 寺院/锚点、固定愿文、命令 ID | 已保存红结及版本，或不扣资产的明确拒绝 |

连接后先应用快照，再接续其后的增量；序号缺口重新取快照。公开 `HomeProjection` 包含住址、主人游戏昵称、房屋布局、可见田畦与动物，不暴露钱包、认证标识或完整私有档案。人物移动插值与预测可在客户端进行，土地与经济必须等服务端确认。

持久数据包括账号映射、角色、地权、家园、动物、作物、背篓/库存、钱包账本、命令回执和红结。位置心跳、在线动作、频道人数可以过期，不能让它们的过期删除家园。数据库独立于商城；备份、恢复和同账号多端策略由 Codex 验收。

M1 先固定坐标约定：右手系、Y 向上、地面为 X/Z，位置使用游戏单位，`yaw` 为绕 +Y 的弧度；不把游戏单位宣传成现实测绘米。每个场景提供 `origin`、道路出口、可走范围及地图投影方法。地块边界是村落坐标中的 X/Z 多边形；房屋、田畦、动物等布局使用相对地块原点的局部坐标。当前各坝已有的接口坐标由适配层转换，不要求整批重写场景。

## 验收门槛

1. 两个真实账号各自创建人物，进入同一村落，互相看见与移动；昵称相同也不能混淆资产。
2. 同时申请同一地块只能一人成功，且只扣一次；另一人能取得相邻地块，两家的房、田、动物都能看见。
3. A 完成种植/饲养、收获进背篓、集市卖货；B 不能操作 A 的经济资产；重复请求不重复扣发。
