## 先读这个

安和里是一片可以长期生活、看见邻居的德宏原野。所有参与共享世界的玩家先注册自己的游戏角色，再进入同一套世界，在村落选择各自的地块安家，以游戏内安币买地、养动物、种植、出售产物，再步行或骑马去瑞丽总佛寺静坐、祈福、挂红结。别人下线后，家和田地仍在；回来能接着生活。

地图以主干线串联主景区、村落与家园，形成可步行、可骑马连续到达的大地图。地形可以按区块加载，但道路、位置与方向需要衔接，不能把菜单切换几张独立场景当作连续大地图已经完成。首轮先打通瑞丽的一条生活主线，再扩展德宏五区。

参考“网上南宁”的是可辨认的地方、人物在世界中活动、公共空间与多人共同在场的产品类型。视频中预告的多人模式尚未由本项目实际试玩核验，不能把宣传内容当作服务器或性能依据。安和里保持自己的德宏自然环境、原野交通和治愈节奏。

当前免费、不充值、不提现、不接商城支付。“赚钱”只指游戏内安币。动物不因缺席死亡，离线不收地，不做地皮炒卖、战力排名、断签惩罚或付费祈福。寺院仪式不增加生产收益，不承诺现实好运。

## 地图应该大在哪里

世界使用德宏五区的稳定 ID：`ruili`、`mangshi`、`longchuan`、`yingjiang`、`lianghe`。这是游戏化地理，不是现实土地交易、准确测绘或古代德宏复原；瑞丽总佛寺是共同的精神与社交中心，尚无寺院官方合作或准确建筑复刻。

地图分四层：

| 层次 | 玩家体验 | 实现职责 |
| --- | --- | --- |
| 世界总览 | 看五区、自己家、好友所在区域与路线 | 稳定区域/路线目录，区域加载 |
| 坝区 | 可辨认的山、水、田、树林、集市、村路和山林入口 | 分块地形、碰撞、道路与地标 |
| 共享村落 | 沿村路看见真实邻居的房屋、农田和动物 | 持久村落、地块目录、邻近订阅 |
| 自己的地块 | 建家、种养、装饰、日常照料 | 地块边界、经营锚点、归属权限 |

连续地图采用“主干线 → 主景区/公共目的地 → 村落支路 → 各自家园”的结构。主景区之间有可辨认的道路、岔口、桥与地标；玩家可以给家门口自建支路并接入公共路网，公共道路不能穿过私人经营区。安家不强制接路，未铺路的合法陆地仍可步行到达。世界总览与小地图展示真实道路和地形，不能因玩家没修路就把可走空地标为封锁。

先把瑞丽的一片河谷村落与总佛寺通路做好：出生歇脚处、相邻地块、井边或榕树下、系统集市、步行/骑马主干线、寺院和红结树。从出生处到村落、家门口、集市与寺院应能沿路连续移动；跨分块时承接当前位置和朝向，加载失败留在最后安全点。先形成有内容的连续生活路线，再以同一契约扩展五区，避免只扩大平地。

每个村落保留公共道路与样板地块，同时允许在合法空地自由选址；不允许玩家圈住公共路、寺院入口或其他人的房子。自由选址在联机版需要服务端登记地块边界、校验相交和计价，当前已实现的服务端目录买地接口尚不具备这一能力。村落满了由服务端扩展同地区新村落，并提供访友定位；不制造“全服只有少量地皮”的压力。既有村落及住址保持稳定，不重新随机分配老玩家。

共享地权不随在线频道改变。同一村落可有多个在线频道，房屋和地块投影一致；好友可会合到有容量的同一频道。人数满时提示真实情况，不伪造同屏在线人数，也不承诺全服几千人同时在一台手机上绘制。

小地图至少显示自身朝向、村路/桥、家、系统集市、寺院、目的地和区域出口；只有真实已同步玩家才显示邻居在线标记。支持选目的地、取消路线、返回自己家位置。路径不可达、未加载和断网要有明确反馈；地图定位不直接传送。

## 一人一角色与持久家园

服务端验证账号后确定唯一 `playerId`；所有共享世界玩家均需完成自己的角色注册，未建角色时先展示创建流程，创建成功后再进入角色与安家流程。外观、昵称和家名是角色资料，换设备仍是同一个人，不能通过改名或重装再次注册领取资产。首轮用有限的服饰/发型/颜色选项，避免先投入复杂捏脸编辑器；不能用昵称当唯一身份。昵称等用户输入按平台要求校验，首轮公共愿文使用固定选项。

新世界标识统一为：

| 字段 | 含义与不变量 |
| --- | --- |
| `worldId` | 同一持久世界；不随登录重新生成 |
| `regionId` | 已有五区 ID，保留不改名 |
| `settlementId` | 已有聚落样式目录，兼容旧选址资料 |
| `villageId` | 该地区中一个持久村落，不等同于临时频道 |
| `plotId` | 全局唯一的游戏地块，归属以服务端为准 |
| `homeId` | 玩家的家园资产，迁居不重发余额、动物或物品 |
| `instanceId` | 临时在线频道；不拥有地权 |
| `chunkId` | 地形/邻近数据订阅分块，与地权分离 |
| `playerId` / `assetId` | 稳定玩家与资产 ID，不由画面临时生成 |

买地流程：查看可用地块或合法自选位置及配置价格 → 确认 → 服务端在一次事务内检查边界、占用与余额、扣币、登记归属、写回执 → 确认后展示自己的家。目录买地已有服务代码，自由选址事务仍待扩展。首轮一个主家园，允许迁居；本机试玩同坝与跨坝搬家免费，房屋、田地、动物、库存及进度随家迁移，余额不重发，旧位置释放。未来联机迁居也必须原子更新地权与资产，不把客户端位置直接当成已获准土地。

两人同时买一块地，只能一人成功，失败者不扣币。网络超时重试使用同一 `commandId`（作为玩家域内幂等键）；先查询或返回原回执，不再扣一次。客户端不得乐观展示“买地成功”后才尝试保存。

下线只移除在线人物，房屋、田地、动物及红结继续保存。长期离线不失去家园；离线产出上限沿用配置，结算以服务端时间为准。首轮经营只能由主人操作；访客可观察与做无经济影响的友好动作，不能拿走收获、卖动物或修改布局。

## 经营与安币

维持现有免费版手感，本机新玩家的初始安家启动金为 **1000 安币**。旧档不重置、不取整、不自动补差。本轮另增独立的 **一次 3000 安币试玩补给**：玩家主动从大厅领取，和领取标记一起事务保存，失败不入账，保存后重进不重复领取；新旧本机档均可领取一次。清除本机档案后无法证明是否同一玩家，不能据此保证跨设备只发一次。共享世界的一次性发放由下述服务端注册事务保证，不包含这份本机补给。原网页农场的 `src/economy-config.js` 是另一路规则，不随此次小游戏调整而重算。

联机安家启动金只能在服务端确认新账号首次创建角色时，以唯一发放记录和钱包事务发放一次；重试返回原结果。已有服务端档案保留原余额，重新登录不补到 1000。本机试玩的旧余额只继续保存在原本机档案，不能被客户端提交为联机资产、叠加到启动金或凭改名再次领取；本机进度如何申请导入需独立迁移规则，本轮不自动导入。

小游戏仍以 `wechat/vendor/preview-economy.cjs` 为准：买地、动物、种子、建屋、马匹、生产周期、售价、上限和现有小确幸奖励均保持；本轮新增补给与道路费用另列，不能用旧模拟报告或 Muse 距离地价参数整体替换。首块地仍按当前价格购买，不因免费发行或发放启动金自动改成零价、再叠加免费券；当前样板地 400、自选地 600 安币。自费修路为 `Math.ceil(长度) * 2` 安币，长度是游戏单位，不是现实测绘米。新增共享地块目录的面积和经营容量需要与 Muse 的实际布局对齐。

`买地/购买动物/种植/浇水/喂养/收获/卖货` 是服务端命令，客户端只提交意图、实体 ID、预期版本和幂等键。服务端检查主人、库存、价格、容量、时间及次数，原子提交钱包、资产和回执；不能上传整份本机 JSON 覆盖权威资产。

不做玩家自由转账、地块转售或现金提现。当前“集市”仍是系统固定价格回购；玩家交易另行立项。狩猎如纳入新世界，结果及次数由服务端判定，不接受客户端传入“成功=true”直接发钱。

账本使用整数最小单位，已固定 `100 coinMinor = 1 安币`；启动金为 `100000`，标准样板地为 `40000`。这种单位可精确表示试玩中的 `0.5 安币`，但本轮未导入旧资产。未来迁移必须精确换算并测试，不能取整改变余额。正式常规交通是步行/骑马；现有试玩回家/水晶快捷入口另行收敛，本文不直接更改它们。

保留未来经济配置版本和按来源/去向的观测：登录、在线、经营、狩猎、活动入账，买地、动物、种子、建屋、马匹消耗，以及余额快照、登录和停留。首轮不采用 NPC 每日 80 安币上限、45 天动物退休、收费月卡或充值重调。新增祈福和挂红结不额外发币、不提高产量；现有静心完成小确幸及领取 40 安币的流程沿用现行配置，奖励仍走原活动命令。

## 寺院与红结

目标中的瑞丽总佛寺既能独处，也能和真实朋友同时到达，提供静坐、木鱼、念珠、礼拜、饮茶等体验，并有树上/架上红结锚点。这些是目标范围，当前瑞丽仅有姐勒金塔山脚的合掌、礼拜、静坐和绕行，尚无总佛寺场景、敲木鱼或持久红结。马匹在寺院外停留，人物步行入院，不能因到寺院而扣钱或要求完成经营任务；也不能要求先祈福才继续种植、收获或安家。

祈福分为动作与记录：礼拜/合掌是临时人物状态；红结是持久记录，使用 `knotId, ownerId, templeId, anchorId, wishPreset, createdAt, revision`。复用总佛寺 ID `ruili-temple`。首轮固定祝愿如平安、家人、健康、学业、感谢，不接受自由文本，不与收益倍率绑定。

旧版心灯两分钟消失、服务重启即清空，不能直接改个名字充当持久红结。祈福免费；不做功德榜、付费愿力、好运概率或跨寺院收入比较。

## Codex 要交付的服务契约

以下是完整 v2 设计。世界引导、首次注册、地块、买地命令与回执已有本机实现，实际请求形状以 `SHARED_WORLD_API.md` 为准；世界连接票据、订阅和红结仍待实现。独立服务不复用旧匿名 `/ws` 的身份票据，也没有线上地址。未来微信登录会话用于换取短期、限定世界的连接票据；票据不放 URL 或日志，匿名来客不能取得地权。本机开发身份与 fixture 只能用于测试，不可当作真实微信账号或已上线多人能力。

| 接口/能力 | 输入 | 服务端结果 |
| --- | --- | --- |

| 首次角色注册 | 已验证账号、`avatarId` 预设、命令 ID；首版昵称由服务端预设 | 原子创建自己的角色与一次性 1000 安币启动金记录；同命令重试返回原回执，新命令重复注册明确拒绝，不再发放 |
| `GET /v2/world/plots` | `worldId, villageId` | 地块边界、当前归属公开投影、价格及版本 |

M1 先固定坐标约定：右手系、Y 向上、地面为 X/Z，位置使用游戏单位，`yaw` 为绕 +Y 的弧度；不把游戏单位宣传成现实测绘米。每个场景提供全局 `origin`、道路出口、可走范围及地图投影方法。当前地块的 `origin` 与 `bounds` 均在村落局部坐标中，渲染时再应用村落到世界的转换；房屋、田畦、动物等布局使用相对地块原点的局部坐标。样板村没有最终世界坐标，不能把不同村落按同一全局原点叠放。当前各坝已有的接口坐标由适配层转换，不要求整批重写场景。

## 验收门槛

1. 两个真实账号各自注册人物；新玩家一次性获得 1000 安币，重试、重登、换设备不重发，旧余额不改变。本机旧余额不能上传冒充联机资产。两人进入同一村落，互相看见与移动，昵称相同也不能混淆资产。
2. 同时申请同一地块只能一人成功，且只扣一次；另一人能取得相邻地块，两家的房、田、动物都能看见。
3. A 完成种植/饲养、收获进背篓、集市卖货；B 不能操作 A 的经济资产；重复请求不重复扣发。
4. 两人沿路步行/骑马到寺院，入院下马，祈福、挂红结且彼此可见；新增祈福/红结不额外发币或提高产量，现有静心及小确幸领取奖励保持。
5. 断线、切后台、响应丢失、服务重启、长时间离线及换设备后，地权、动物、田地、余额和红结仍在；失败不显示成功。
6. 两人闭环通过后再测 24 个真实连接的公共区域；记录客户端帧时/内存、服务端延迟/错误率。24 人只是起测值，不能据旧服务配置承诺新世界容量。
7. 再测多村、多频道与长时间运行，扩到五区。没有负载与真机证据不宣传千人同屏。
8. 从出生处经主干线连续走到村落、自家门口、集市与总佛寺；小地图位置、方向、分岔与出口一致。分块切换承接角色，加载失败回到安全点，不能用菜单切景替代这项验收。

每轮改动运行 `npm test`、`npm run build`、`npm run build:wechat`、`npm run verify:calendar`；涉及场景和 UI 再跑 `npm run test:ui` 与微信真机检查。截图、报告、构建、临时文件均留在 D: 项目，公开提交不带凭据、真实玩家隐私或数据库。

年禧商城其他模块及 `public/calendar/` 不动。本轮 GitHub 交接不执行生产部署或微信提审。
