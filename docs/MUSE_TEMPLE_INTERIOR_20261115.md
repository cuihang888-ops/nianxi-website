# 总佛寺内景施工说明（Muse，2026-11-15）

用户口径（2026-11-15 21:33 / 21:38 / 21:53）：「安和里寺庙大厅怎么没场景了，人要能进去啊，进去拜神，祈祷，静坐」，加上点名的敲木鱼、跪拜、盘佛珠（原话「盘沙珠」，按盘佛珠/念珠实现）。本轮把芒市总佛寺从只有外景的空壳，补成能走进去的室内场景。

## 口径（按用户已定规矩，不新增限制）

- 进寺不设门槛、不限次数、不计时收费；寺内零经济：不发币、不加产量、不做交易、不放充值入口。
- 骑马者先下马才能进寺（沿用金塔祈福的现成处理：骑马时寺门动作区让给「下马」，大厅行点击提示先下马）。
- 殿内**静坐**与大厅每日**「静心」**是两回事：静坐纯粹坐着，想坐多久坐多久、随时起身，不写每日状态、不给币；静心领取流程一字未动。
- 五个动作都是安静的小状态机，可随时中断走开，不计数、不打分、不连击判定。

## 落位与进出规则

- 内景是芒市世界内的独立室内区：大殿建在远置坐标 **(600, 0)**（殿外带一圈草坪盘与石台，不与坝面任何地块/路网重叠），与总佛寺外景是同一个世界、同一套跟随相机与摇杆，不新造移动系统。
- 寺门锚点在总佛寺寺体中心 (−58,−58) 沿门向（寺体旋转 0.35）16.5 单位处 = (−52.34, −42.5)，半径 7，恰在寺体碰撞圈外缘；与大厅锚点 (−38,−44) 相距约 14.4，大于大厅交互半径，不抢按钮。
- 走到寺门出现「进寺」→ 点击进入：位置转移到殿内南侧入口 (600, 7.4)、面朝佛龛（yaw π），并记住进寺前的位置；殿内南侧出口锚点 (600, 10.3) 出「出寺」，回到进寺前的位置。大厅面板另有一行「去总佛寺里坐坐」作引导入口（仅芒市坝显示），点击直达殿内，出寺同样回到点开面板前的位置。
- 玩家位置从不落档（每会话在出生点重生），且场景层任何一次传到殿外矩形之外的落位都会自动退出殿内模式并复位灯光——玩家在殿内退出游戏，重进必然落在寺外，不会卡在室内。
- 殿内碰撞：内腔矩形钳制（半宽 14.6 / 半深 10.6）+ 圆碰撞（佛龛台+供桌、四根梁柱、木鱼案、佛珠架、两根长明灯柱），通道能走，墙体/佛龛/供桌挡人。
- 光线：进殿后环境光与日光按比例压暗（×0.5 / ×0.3），殿内两盏暖色点光（佛龛前 0xffbf74、大殿 0xffd9a0）接管氛围，雨幕在殿内强制关闭；出寺恢复室外光。相机在殿内钳在大殿内腔里，不出墙、不穿顶。

## 殿内陈设（傣式寺庙、原始底色、沿用木/石/竹/金材质族）

石地板与中央拜道、南墙门洞（带门楣）、双坡屋顶与脊梁、四根梁柱；北侧佛龛（台阶、背屏、金色光背、金身佛像）、供桌与三只供碗、两盏长明灯；一排五只蒲团；东侧木鱼案（木鱼+敲棒+声波纹环）；西侧佛珠架（托台、小架、垂珠环与流苏）与玩家手持念珠串（12 颗木珠）。

## 五个动作（靠近对应位置出按钮）

锚点都在蒲团排（z = −4.4）与木鱼案一线；多个锚点半径重叠时按最近点裁决（祈祷与盘佛珠锚点相距 1.4，靠这一条区分）。

1. **拜神（跪拜）**：蒲团中位「礼拜」→ 传送到蒲团、面朝佛龛 → 合掌 1.5 秒（姿态 1）→ **跪拜** 3 秒（姿态 2）→ 自动起身。跪拜是真跪姿：kneelBlend 缓动跪下（身体下沉 −0.52、双腿折跪 −1.45），再随 bowClock 走一轮叩首起伏（俯身 0.55·dip、双臂前伸触地意象），与静坐的盘坐姿（下沉 −0.42、身直、腿 −1.35·restBlend）在数值与形态上明确区分。中途走开超过锚点半径 +3.5 即静默停下。
2. **祈祷**：「祈祷」→ 面板小选固定五句心愿（平安 / 家人 / 健康 / 学业 / 感谢，不许自由输入，复用取名面板组件）→ 跪坐（resting）+ 合掌（姿态 1）默念 5 秒（与静心同长）→ 完成只在本机存档记轻标记 `rites.templeAt / templeWish`。中途起身/走开（resting 断开）即静默结束、不记标记。
3. **静坐**：蒲团东位「静坐」→ 坐下，不建状态，交给通用「起身」按钮接管；坐下后呼吸起伏放大到看得见：胸廓 scale.y 振幅 0.05（站立时 0.012）、头部 ±0.025、呼吸率 1.3。无计时、无奖励、无次数。
4. **敲木鱼**：木鱼案前「敲木鱼」→ 进入敲击态，行动钮变「敲一下」，每点一次：敲棒落下（0.28 秒摆动）、鱼身轻微脉冲、一圈淡声波纹扩散（0.55 秒）。走开超过锚点半径 +3.5 即结束。本轮**纯视觉、无声音**：全仓没有现成音频通道（无 AudioContext / InnerAudio 调用），不新造，如实说明。
5. **盘佛珠**：佛珠架前「盘佛珠」→ 手持念珠串出现（挂在玩家身上），双臂虚持身前，珠串以 0.55 rad/s 缓缓滚动；点行动钮停下或走开即止，结束提示「佛珠放回架上了」。与敲木鱼同口径：不计数、不计功德、不发币。

姿态实现说明：芒市是独立场景模块（非 dam-world 引擎），本轮为它补齐了 `setPrayerPose / getPrayerPose / setPlayerYaw`（金塔礼拜庭已有同名能力，口径一致：1 合掌、2 礼拜）。一处有意差异：dam-world 里姿态与坐姿互斥，芒市这里**相互独立**——因为祈祷要「跪坐 + 合掌」并存，代码注释已注明。跪姿（姿态 2 的 kneel 合成）是本轮新增能力，金塔礼拜庭现仍为站姿礼拜，后续可按同一数值口径升级。

## 与静心 / 金塔礼拜庭的关系

- 静心：大厅面板的每日呼吸领取（写 jingxinDate、走小确幸任务）完全未动；殿内静坐不写任何每日状态。两者只是时长同为 5 秒量级，语义无关。
- 金塔礼拜庭（瑞丽）：锚点、状态机、姿态编号、完成标记（pagodaAt）全部原样；寺庙祈祷标记与 pagodaAt 同族、互不覆盖（validateRites 允许三键并存，templeAt 与 templeWish 必须成对出现、且心愿必须是五句之一，伪造存档过不了校验）。寺内动作不写 pagodaAt，金塔流程也不受影响。
- 引导：玩家闭环的「下一步」引导里金塔祈福那一步之外，大厅面板在芒市坝多一行「去总佛寺里坐坐」（副文案：拜神 · 祈祷 · 静坐 · 敲木鱼 · 盘佛珠），不强制、不倒计时；其他坝不显示。

## 红结说明

红结架与挂结记录是共享世界 C3 / M2 的事：**本轮不挂结、不做红结架、不假装持久化**。本轮只做礼拜空间本身（能进、能拜、能坐、能敲、能盘）。将来挂结时，殿内现有的蒲团排与佛龛两侧灯柱之间留有空位，可再议落位。

## 金塔塔内后续复用

瑞丽金塔塔内若后续要做成可进入内景，直接复用本系统：远置室内区 + interiorResolve（矩形钳制 + 圆碰撞表）、进出锚点（door/entry/exit）、殿内灯光接管（refreshLights 模式）、相机内腔钳制、姿态合成（合掌/跪拜/坐姿/呼吸）。金塔祈福状态机里的 contract prayer anchor (0, 3.5) 已预留，塔内落位时对齐即可；控制器侧把 templeAction 的锚点表换成塔内锚点即可复用同一套状态机骨架。

## 服务端对齐

- 进出寺与五个动作都是**瞬时态**（只存内存），无需服务端介入，也不存在跨玩家同步问题。
- 唯一落档的是祈祷轻标记 `rites.templeAt / templeWish`（本机存档，形状已过 validateState 校验），将来云存档上线时可随存档整体上云，字段形状不变；它不参与任何经济与资格判定，服务端无需为它单设接口。
