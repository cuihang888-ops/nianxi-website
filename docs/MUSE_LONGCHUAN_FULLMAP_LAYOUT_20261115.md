# 陇川全域大地图布局（2026-11-15）

收件人：Codex。配套数据模块：`wechat/vendor/longchuan-region.cjs`（本文所有数值从该模块抄录，两边以模块为准；模块测试 `tests/longchuan-region.test.mjs`）。
基线：`muse/shared-world-scenes` @ `8609905`（瑞丽全域图定稿之上）。用户要求原话：「顺便把其他城市的地图一起做了」，标准与瑞丽全域图一致：「能做多大做多大，大概位置的标志性的东西还是要有」，并为几千人安家留足村落基址（容量账见 §7）。
本契约只定全域布局与坐标口径，不表示规划区已建成、已可玩；现状与规划在数据里逐项用 `status: built | planned` 区分（见各表）。

## 1. 范围与两层口径

全域坐标用**坝内坐标**（与现有陇川场景 `longchuan-scene.cjs` 的 spec 同一套：右手系、Y 向上、北 −Z、东 +X，`yaw = atan2(dx, dz)`，游戏单位不宣传为现实测绘米）。现有锚点一律不挪位，总图只向外扩：

| 层 | 范围（坝内坐标） | 面积量级 | 含义 |
| --- | --- | --- | --- |
| 现状 `playableNow` | 椭圆 cx0/cz0、rx **250**、rz **205**（包围盒 x∈[−250,250]、z∈[−205,205]） | 500 × 410 | 现有陇川场景已覆盖、已可玩的范围，数值逐字抄自 `longchuan-scene.cjs` 的 spec `bounds` |
| 总图 `masterPlan` | x∈[**−620, 660**]、z∈[**−480, 480**] | **1280 × 960** | 陇川全域总图规划范围：西抵铜壁关方向、东过城子去遮放、北抵三江入境谷口、南含南宛河出坝口与章凤边关 |

模块字段：`REGION_BOUNDS = { playableNow, masterPlan }`。两层之外没有第三种口径：不在 playableNow 内的，一律是规划，不得在客户端呈现为已可玩。

## 2. 坐标与投影

- 本区没有村落级契约模块（不像瑞丽有 `shared-village.cjs`），全域坐标即坝内坐标，不设第二套换算；村落开村时的村内排布在各村开村前按瑞丽村落契约同标准另交。
- 全域小地图投影（模块 `worldToMap` / `mapToWorld`，互逆，测试覆盖）：中心取总图几何中心 (20, 0)，比例 **0.5 地图单位 / 游戏单位**（总图映为 640 × 480 地图单位）；朝向定义与瑞丽版相同——map.x 东为正、map.y 向下为正（南在下、北在上，指北向上）。地图定位只读，不触发传送（交接文档红线不变）。

## 6. 马场与传送

陇川是全图的马源：马场 (86, −58) 是现有场景已建的围栏马场（场内有马），传送水晶 (99, −46) 就落在场边——本区的传送落点与马场同处，是现有场景的既定格局，总图原样继承、不另设传送点。玩家在本区领养马匹（价格口径沿经济配置，马价带宽 1200 为现行值）、与马的亲近度养成等玩法锚点都在马场；东线古道是马队东出遮放的线。马匹的持久归属与跨区携带属服务端目录事项，本契约只定落位与动线。

### 7.2 容量账（把数算清楚）

- **每村首期 8 块**：与瑞丽村落契约的定稿排布同口径（30×32、带土巷与公共保留的一整排村格局），新村开村即按这个数起步，不用临时凑地。
- **每村上限 32–48 块的估算依据**：单块地 30×32 = 960；连上土巷、土径、村心公共保留与地形损耗，平均每户实际占地约 1700–2200 游戏单位²；单个基址周边的可安家地带约 7–10 万单位² → 约 32–48 户。逐村按地形给值（坝田最开阔 48、河谷/山麓最窄 32，见上表），不是一刀切。上限是**总图估算**：每一轮实际扩村排布仍须按村落契约的判定（压路 ≥ 8、压水、保留区）逐块校验后才生效。
- **陇川一区合计**：11 处基址，首期 **88 户**，全图扩满 **428 户**（模块 `REGION_CAPACITY` 由基址表求和，文档与测试都用这个数，不另算一份）。
- **五区合计推算口径**：瑞丽已定稿 420 户、盈江 424 户（同日另交）、陇川 428 户；芒市、梁河两区尚未做全域图，按同标准每区约 400–480 户推算，**五区合计约 2000–2400 户**，基址加密可达约 3000 户量级。这是量级推算，不是承诺数：每区的实际数以各自全域图落位为准。
- **在线承载口径（与交接文档一致，不另立说法）**：几千人同时在线靠**多村落 + 邻近订阅 + 在线频道**承载——玩家分散在几十个村落与公共区里，客户端只绘制邻近范围的人；**地权与频道分离**：家园占地是持久目录数据（主人不在线，地和房子也在），频道只是临时在线分片，换频道不换地。**不承诺几千人同屏**，也不伪造在线人数。村满了由服务端按本表的预留基址开新村（新 `villageId`），**老村坐标与已分配地块永不重排**——先住下的人，家永远在原地。

## 9. 打折、纠偏与待确认（如实记录）

- **护国古关方位纠偏**：2026-11-13 地方图设计稿把护国古关画在坝东北、南宛河源头一带；现有场景 `longchuan-scene.cjs` 把关楼建在坝西 (−150, 96)。总图以现有场景为准（built，锚点不挪），设计稿的东北落位不再采用；名称与「护国」的来历（南宛河发源护国山）仍在，关楼本体位置与源头不在一处——将来场景实现轮次若要正名/移位，另行评估，本轮只记录出入。
- **总图大 ≠ 现在就能玩那么大**：masterPlan 是规划范围，其内 planned 的地形、水系渲染、碰撞、植被都还不存在；当前唯一可玩范围仍是 playableNow 椭圆。1280×960 是「能做多大做多大」的总图尺度承诺（落位与目录先行），不是现状描述。
- **城子、景罕只落位**：两处镇级聚落点本轮只定位置与路网挂接，不定内部格局；镇内是否设第二集市、驿站功能，等服务端目录与经济配置冻结，本契约不预设（系统集市仍只有章凤一处）。
- **村落上限是估算**：§7 的 32–48/村与五区 2000–3000 户是按占地口径的量级推算；逐村扩容要在后续排布轮次逐块过校验，校验不过就降上限，不硬塞。
- 待 Codex 冻结项集中在 §8 表格：世界/村落目录形状、villageId 分配、预留基址启用顺序、plots 编码与价格单位（沿瑞丽村落契约）。
