# 芒市全域大地图布局（2026-11-15）

收件人：Codex。配套数据模块：`wechat/vendor/mangshi-region.cjs`（本文所有数值从该模块抄录，两边以模块为准；模块测试 `tests/mangshi-region.test.mjs`，并与现有场景锚点做交叉一致性断言）。
基线：`muse/shared-world-scenes` @ `8609905`（瑞丽全域图定稿之上）。用户要求（2026-11-15）：「顺便把其他城市的地图一起做了」——其余各区按瑞丽同一标准出全域图：能做多大做多大、标志性东西按真实大概位置摆、为几千人同时在线留足安家地（容量账见 §7）。
本契约只定全域布局与坐标口径，不表示规划区已建成、已可玩；现状与规划在数据里逐项用 `status: built | planned` 区分（见各表）。

## 1. 范围与两层口径

全域坐标用**坝内坐标**（与现有芒市场景 `mangshi-scene.cjs` 的 landSpec 同一套：右手系、Y 向上、北 −Z、东 +X，`yaw = atan2(dx, dz)`，游戏单位不宣传为现实测绘米）。芒市场景是独立模块（不走通用坝引擎），锚点全部抄自该文件本体。现有锚点一律不挪位，总图只向外扩：

| 层 | 范围（坝内坐标） | 面积量级 | 含义 |
| --- | --- | --- | --- |
| 现状 `playableNow` | 椭圆 cx0/cz0、rx **265**、rz **215**（包围盒 x∈[−265,265]、z∈[−215,215]） | 530 × 430 | 现有芒市场景已覆盖、已可玩的范围，数值逐字抄自 `mangshi-scene.cjs` 的 landSpec `bounds` |
| 总图 `masterPlan` | x∈[**−660, 680**]、z∈[**−480, 480**] | **1340 × 960** | 芒市全域总图规划范围：西抵坝西田野与遮放走廊、南含坝南与勐戛道、东过雷牙让山、北抵轩岗/梁河谷口 |

模块字段：`REGION_BOUNDS = { playableNow, masterPlan }`。两层之外没有第三种口径：不在 playableNow 内的，一律是规划，不得在客户端呈现为已可玩。

## 2. 坐标与投影

- 本模块坐标即坝内坐标，不存在第二套村落坐标换算（瑞丽的村落坐标平移是瑞丽村落契约特有，本区无此层）。
- 全域小地图投影（模块 `worldToMap` / `mapToWorld`，互逆，测试覆盖）：中心取总图几何中心 (10, 0)，比例 **0.5 地图单位 / 游戏单位**（总图映为 670 × 480 地图单位）；朝向定义与瑞丽版相同——map.x 东为正、map.y 向下为正（南在下、北在上，指北向上）。地图定位只读，不触发传送（交接文档红线不变）。
- 交叉一致性已由测试断言：总佛寺 (−58,−58)、大厅 (−38,−44)、集市 (4,34)、水晶 (−0.5,35.5)、出生落点 (4,52)、孔雀湖 (112,−18) 与现有场景本体逐字一致；集市另与 `preview-discovery.cjs` 的 `MARKET_POS.mangshi` 同点互验；两个现有基址与场景 `buildSite` 落位一致。

## 6. 中枢地位：总佛寺与出生地

- **总佛寺是全世界的公共中心**（交接文档口径）：寺院目录 id `ruili-temple` 的本体就在本坝西北 (−58,−58)，大厅亭紧邻寺前 (−38,−44)——五区大厅里芒市这一处就设在总佛寺前，与「大厅在寺前」的既定格局一致。祈福与挂红结的动作锚点、记录形状以交接文档与寺院契约为准，本契约只确认本体落位，不另立一套。
- **出生地在本坝**：安和里庭院是独立场景（出生地本体），玩家从庭院进入大世界时落在本坝出生点 (4,52)——集市南侧、芒市大道旁，抬脚就是集市与大道，南下走廊、北线、轩岗道、勐焕大道四个方向都从坝心展开。中枢坝的路网密度（六条线）高于其他四区，是有意的：这里是所有人出发与回流的地方。

### 7.2 容量账（把数算清楚）

- **每村首期 8 块**：与村落契约的定稿排布同口径（30×32、带土巷与公共保留的一整排村格局），新村开村即按这个数起步。
- **每村上限 32–48 块的估算依据**：单块地 30×32 = 960；连上土巷、土径、村心公共保留与地形损耗，平均每户实际占地约 1700–2200 游戏单位²；单个基址周边的可安家地带约 7–10 万单位² → 约 32–48 户。逐村按地形给值（坝田最开阔 48、轩岗道旁谷地最窄 32，见上表），不是一刀切。上限是**总图估算**：每一轮实际扩村排布仍须按村落契约的判定（压路 ≥ 8、压水、保留区）逐块校验后才生效。
- **芒市一区合计**：12 处基址，首期 **96 户**，全图扩满 **460 户**（模块 `REGION_CAPACITY` 由基址表求和，文档与测试都用这个数，不另算一份）。芒市是中枢坝，基址数与总量为五区之首，是有意的。
- **五区合计进度**：已定稿全域图三区——瑞丽 420 户、芒市 460 户、梁河 420 户，合计 **1300 户**；陇川、盈江两区全域图另行施工中，五区总量待五张图齐后按各区实际落位重算（按当前三区口径推算仍在约 2000 户量级，加密基址可达约 3000 户量级；量级推算，非承诺数）。
- **在线承载口径（与交接文档一致，不另立说法）**：几千人同时在线靠**多村落 + 邻近订阅 + 在线频道**承载——玩家分散在几十个村落与公共区里，客户端只绘制邻近范围的人；**地权与频道分离**：家园占地是持久目录数据（主人不在线，地和房子也在），频道只是临时在线分片，换频道不换地。**不承诺几千人同屏**，也不伪造在线人数。村满了由服务端按本表的预留基址开新村（新 `villageId`），**老村坐标与已分配地块永不重排**。

## 9. 打折、纠偏与待确认（如实记录）

- **总佛寺位置以现有场景为准**：2026-11-13 地方图设计稿把总佛寺画在城镇中心、庭院在其南；现有场景把总佛寺建在西北 (−58,−58)、集市居中 (4,34)。两者是示意与实现的差异，总图按**现有场景**落位（built 不挪），设计稿只用于 planned 地标的相对方位参考。同理，设计稿的孔雀湖画得更靠东、更大，现有场景湖体在 (112,−18)，以场景为准。
- **勐焕大金塔/银塔尚无塔体**：真实芒市的勐焕大金塔立在雷牙让山上、银塔对峰；现有场景东沿只有山体（built），没有塔体建模。总图按真实方位把金塔落东山 (350,−160)、银塔落其南 (330,90)，均为 planned；塔体建模与登塔道（金塔大道）是后续场景实现轮次的事。
- **总图大 ≠ 现在就能玩那么大**：masterPlan 是规划范围，其内 planned 的地形、水系渲染、碰撞、植被都还不存在；当前唯一可玩范围仍是 playableNow 椭圆。1340×960 是「能做多大做多大」的总图尺度承诺（落位与目录先行），不是现状描述。
- **城内大道网只落主轴与横贯线**：设计稿的城内大道是多条纵横线（金孔雀/芒市/团结三条纵线 + 勐焕大道横线）；总图把纵线收敛为现有古道这一条主轴（芒市大道）加一条横贯线（勐焕大道），不逐条复刻现代路网——原始社会底色下坝心不需要三条平行大道，收敛口径在此写明。
