# 开放式安家 + 玩家自费修路（Muse，2026-11-15）

## 1. 用户口径

2026-11-15 21:18 拍板：

> “安家的地方以道路为标，沿路建房安家；做成开放式的，想在哪安家就在哪安家；
> 可以自己修路但是费用自己出，修了路只要通路了就可以开放安家，
> 就是让玩家可以自己来画城市。”

同日晚 21:29 追加总原则（优先级高于一切细则）：

> “留足可玩性跟开放性，不要限制太多规则。”

这是 2026-11-13 底色原则（城镇乡村不预设、由玩家共建长出来、贡献记名不排名）的
正式落地，也是现有自选地（checkPlotSpot / claimCustomPlot）的升级，不是推翻：
固定村落基址保留为「已经通路的新手村落」，自选地升级为全图开放安家。

## 2. 设计原则（少规则）

**只拦物理上不可能与侵犯他人之地的事，其余全开放。**

- 修路只剩三条硬性：① 不压已划地块；② 不压地标建筑本体；③ 余额够。
- 通路判定只剩一条距离：地块离路网太远就不行，别的都不管。
- 费用只剩一个数：2 安币/单位。
- 地块自身的老物理拒绝（在水面/丘陵/大厅/水晶/已占上不能安家）是物理常识，
  不是新规则，保持不动。

## 3. 路网定义

每坝的路网 = 以下三者之和，全部是坝内坐标的线段集：

| 来源 | 数据 | 说明 |
| --- | --- | --- |
| 场景自带古道 | 各 scene spec 的 `roads` 字段（折线数组） | 与各场景 decorate 里绘制古道的 `roadPts` 逐字一致：瑞丽 `[[-190,44],[-110,26],[-40,12],[0,6],[70,16],[140,24],[200,30]]`、盈江 `[[-6,-104],…]`、陇川 `[[-24,-160],…]`、梁河 `[[-4,-180],…]`；芒市独立模块 landSpec.roads = 同一份 roadPts |
| 村落内部土路 | 仅瑞丽湖畔村（M1 契约村） | 村心空地（VILLAGE_COMMONS）中线 + 两条排间土巷（村内 z=18.5 / 53.5），由 shared-village 契约坐标经 `toDamCoords` 换算进 spec.roads。保证 A/B 与村内自选地沿土路安家不受通路判定影响 |
| 玩家自建路 | 存档 `state.roads[damId]` 的两点段 | **一建成即计入路网**，不要求先与主网连通——孤立路段也算数，村落可以先自己长出来，以后再连上 |

几何实现只有一份：`wechat/vendor/dam-world.cjs` 的
`roadSegmentsFromPolylines / distanceToRoadSegments / validateRoadSegment /
checkCustomPlotSpot`，芒市独立模块共用同一份，不另写。

## 4. 通路条件（自选地）

`checkPlotSpot` 在原有物理判定之后、调用方传入路网时追加**一条**判定：

```
地块边缘到路面边缘的距离 = d − PLOT_REACH(7.7) − HALF_WIDTH(5) ≤ ACCESS_RANGE(30)
```

其中 d 是候选点中心到最近路网中心线的距离。超过即拒绝，原因 `road`，
玩家提示：「这里还没通路 · 先修一条路过来」。

- 就这一条。压不压路不再拦：路是平的，住路边、住路口是玩家自己的选择。
- **固定基址地块不受此限**：claimHome 不走 checkPlotSpot，基址视作已通路。
- **老存档祖父条款**：`claimCustomPlot`（存量自选家的恢复/落位路径）不传路网、
  不判通路——已经安好的家永不追溯判定；通路判定只作用于新选点位。

## 5. 修路流程（两点式，在现有行动按钮体系内）

入口：大厅面板一行「修一条路」（副文案「自己出钱 · 通了路才能安家」，
`canvas-ui.cjs` 的 roadRow，控制器每帧 `setRoadRow`）。

1. 点「修一条路」→ 关面板，提示「走到想起路的地方，点『从这里起路』」。
   未登记者先引导登记入住（与安家同门槛）。
2. 走到起点 → 行动按钮「从这里起路」→ 记下起点。**起点随处可起，不验接路。**
3. 走到终点 → 按钮实时显示「铺到这里 · 约 X 安币」（X 为当前长度报价；
   两点几乎重合时显示「再走两步」）。
4. 点确认 → 整段校验（下节）→ 状态层扣费落档 → 路立即渲染并计入路网。
5. 取消：打开大厅面板、切坝/切场景即取消草稿，**不扣费**。骑马时先下马。

接线点：`wechat/home-controller.js` 的 `startRoadMode / roadAction /
handleExternal("build-road")`；进场恢复在 `restoreVisual()` 调
`world.setPlayerRoads(state.roads[dam])` 按存档重绘本坝全部自建路。

## 6. 修路校验（只剩三条硬性）

| # | 硬性 | 在哪判 | 拒绝 |
| --- | --- | --- | --- |
| 1 | 不压已划地块：已认领地块 + 契约/基址地块（含瑞丽预留 C–H） | `dam-world.validateRoadSegment`：整段采样（步长 `SAMPLE_STEP=2`，含两端点），采样点到地块矩形距离 < 条带半宽 1.5 + 0.5 | 原因 `taken`：「这条路会穿过已划好的地 · 绕一绕」 |
| 2 | 不压地标建筑本体占地圈：各 scene spec 的 `landmarks`（金塔/佛寺/塔/刀坊/纵歌场/司署/金葫芦/榕树等）+ 大厅 r6 + 集市 r8 + 水晶 r4 | 同上，采样点进圈（圈半径 + 条带半宽） | 原因 `landmark`：「这里有地标建筑 · 绕一绕」 |
| 3 | 余额够报价 | 状态层 `daily-state.buildRoad` | `INSUFFICIENT_COINS`，不扣费不落路 |

除此之外**全部放开**（都是刻意删掉的规则，勿加回）：

- 可以过水：过水段渲染成简易木栈道（见 §8），同价不加钱；
- 可以贴山脚、穿丘陵碰撞圈（路是贴地条带，不与地形冲突）；
- 长度不限：取消最短段 10、取消最低收费 20；唯一例外是两点几乎重合
  （长度 < 1）不是一条路，原因 `invalid`；
- 不用先接主网：取消起点 ≤6 接路校验，孤立路段合法；
- 与已有路相交自由（天然成路口）；
- 不查坝界：玩家站位本身被地形解析限制在坝内，线段自然落在坝内。

存档完整性护栏（不是玩法规则）：每坝自建路上限 `MAX_ROADS_PER_DAM = 400`
（防存档膨胀）；记录字段 by/at 照常校验（记名要为真）。

## 7. 价格与经济复核

常量单一数据源：`wechat/vendor/preview-economy.cjs` 的 `ROADS`
（紧挨 LAND_BANDS）+ `roadCostForLength()`：

```
报价 = round(长度 × 2)    // 四舍五入，全游戏唯一口径；无最低消费
```

地价不变：安家仍按上一轮 LAND_BANDS 距水晶分档（主城区 600 / 近郊 400 /
远郊 250 / 边地 150）。修路费是独立的一笔基建支出。

账（给 Codex 复核）：

- 远郊选一块 250 的地 + 自修 40 单位路 80 = **330 < 近郊现成通路 400**，
  愿意动手的人反而省钱；
- 边地 150 + 修 100 单位路 200 = **350**，仍然便宜；
- 贴水晶的主城区 600 买的是现成的方便：自带路网，不用修路；
- **新玩家开局不变**：1000 安家金、近郊通路现成 400，闭环恒等式
  1000 −400 −72 +120 −140 +16 +5 +40 = **569** 已由既有玩家闭环测试复验。

按新口径补一句：2 安币/单位低到近乎随手——修路的重点从来不是收费，
是「画城」的乐趣；费用只是让每条路都是一次真实的小决定，不至于满地图乱画。

## 8. 路的呈现

`dam-world` 的 `setPlayerRoads`（芒市独立模块同口径）：

- 土路条带宽约 3（`STRIP_HALF_WIDTH × 2`），夯土材质 `M.road` 与古道同族；
  按 ≤6 单位分块渲染，块间接缝与两端有圆面收边；
- **过水块自动换木料 `M.wood` 并略抬高（y 0.10 vs 0.05）**，连起来就是一段
  简易木栈道/木桥——用现有材质实现，无新资源；
- 进游戏/切坝时按存档把本坝自建路全部重绘（组名 `roads:player`）；
- 路是公共的：建成后永久留在存档里，任何地块判定都把它算进路网；
  路边不立碑，但修路人记名保存在存档与本文口径里（共享世界阶段对应村碑记名）。

## 9. 存档字段与老存档

```js
state.roads = { [damId]: [{ a: { x, z }, b: { x, z }, by, at }] }
// by = 修路人名字（记名不排名），at = 修成时间（epoch ms）
```

- `validateState` 把 `roads` 按**可选字段**校验：老存档没有此字段照常通过；
- `normalizeProgress` 加载时补 `state.roads = {}`；
- 已安的家、已认领的地**永不追溯**通路判定，永不补收费（见 §4 祖父条款）。

## 10. 服务端对齐（C3，只写口径不实现）

共享世界阶段，路是持久共享对象。服务端只需复核**三条硬性 + 扣费**，
不要把客户端已经删掉的规则在服务端加回来：

1. 路记录：`roadId / damId / a / b / builderId（记名） / cost / createdAt`；
   客户端只提交两端点，服务端按同一张常量表（2 安币/单位，round）计价扣费，
   幂等回执防重复提交双扣。
2. 服务端复核：不压他人已认领地块与契约基址地块、不压地标建筑本体占地圈、
   余额够——仅此三条。过水、孤立路段、任意长度均合法，服务端不得以
   「未连通主网」拒绝。
3. **修路不产生路边土地的任何权利**：不许圈地，地仍先到先得、按 LAND_BANDS
   分档价认领。路是公共基础设施，不是炒地工具。

## 11. 与固定基址 / 五区 region 契约的关系

基址表**不作废**：固定基址 = 首期保证容量（五区 57 个基址、456 个初始家、
2152 个上限家的账仍成立），是新玩家落地的下限保障；开放安家 + 玩家修路是
有机增量，从此**总容量由地形决定，基址数只是下限**。玩家先在基址安家、
再沿自己修的路向外长出新聚落，正是「让玩家自己来画城市」的路径。
