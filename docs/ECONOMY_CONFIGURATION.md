# 免费版经济配置

2026-11-13。本轮只抽离配置，不重调经济，也不接充值、支付、提现或商城订单。

## 当前实现

`src/economy-config.js` 是仓库内、随构建发布的共享配置模块。农场规则、马匹价格和界面报价从同一张表读取。模块初始化时校验字段与整数范围，然后递归冻结；存档和动作参数不能覆盖它。

这不是已经上线的服务端远程配置。当前免费网页原型仍以本机存档为准，不能作为付费资产账本。第三期需要由服务端选择并验证配置版本、执行经济动作，客户端只展示服务端返回的版本和结果。

## 第三期接口与验收

- 新经济参数必须使用新配置版本；上线前复跑同一套购买、喂养、收获、出售、补给和狩猎行为模型。
- 当前存档不新增或强制迁移经济版本，旧余额和资产不变。第三期另定老存档余额换算、资产继承和补偿方案，不能静默清零。
- 服务端配置不能直接信任客户端传值。服务端负责配置有效期、余额、限购、收购量与狩猎结果，并记录经济配置版本和流水。
- NPC 每日收购上限、动物退休期、玩家交易市场是待评审的规则变化，不是已经启用的配置开关。本轮不改变这些玩法。
- 充值、虚拟支付、提现、现金兑换均不在当前配置中。

## Muse 模拟报告核对项

Muse 的 90 天模拟报告已作为三期设计输入收到，但尚未获得可执行脚本，不能声称已复跑验证。需要先统一以下口径：

1. 第一轮声称使用现行每日补给 120 安币，但 A 类 90 天保底收入写为 630，实际对应 `(登录 5 + 在线 2) x 90`；这两套发行规则不能混在同一轮里。
2. 必须明确每次上线的喂食次数、喂食时间与收获次数。当前规则只在喂食覆盖周期内产出，并受单只待收 12 的上限约束；仅有“在线 1 小时”不能推出持续一小时产出。
3. C 类每月充值 10 元、90 天合计记 2000 安币，需要明确首次充值时间与月度边界。免费版不运行这一策略。
4. 第三轮的 80 安币日收购量和 45 天盛产期需连同新内容消费、活跃分布、离线行为一起复跑，不能直接作为已验证的正式运营参数。

验证：现有规则回归覆盖喂养、产出上限、重复领取、余额、库存、旧存档与狩猎；新增测试锁定 `free-v1` 数值、拒绝非法配置，并验证存档/action 无法注入配置。
