# 安和里微信小游戏免费版迁移计划

日期：2026-11-13

本文针对安和里首发的微信小游戏免费体验版。它以当前网页原型为规则基线，先验证真实微信环境中的游玩、存档和恢复，再扩展完整德宏世界。小游戏首发不接充值、虚拟支付、商城订单、提现或版号相关工作；这些能力保留接口位置，但不进入本轮构建。

## 目标与边界

首发版本应让玩家在微信内完成一条完整但轻量的体验：微信登录、进入安和里、在庭院与山谷之间移动、照料动物和土地、进入猎场完成无血腥狩猎小游戏、获得安币、保存进度、下次打开或换设备后恢复已确认的进度。首发同时提供必要的数据埋点，用来观察体验是否顺畅和玩家是否愿意回来。

免费版沿用现有 `src/farm-state.js` 的数值和行为，不为了未来充值提前改变产出节奏。现有每日补给 `+120` 保留，不叠加“登录 +5”或“在线每小时 +2”。累计签到、小确幸和回流礼列入后续内容包，先不改变本轮数值。玩家不能充值、提现或把安币兑换成人民币；安币只作为当前游戏内的游玩资源。日历与自动罗盘原文件不迁改，微信端承载方式作为独立验证项；未验证前不承诺可直接打开网页日历。

本轮不包含：五区完整可行走大地图、玩家间交易、真实云端钱包、商城会员绑定、虚拟支付、广告变现、现金提现、版号申请和线上正式发布。

## 目标架构

小游戏使用四层结构，避免把微信 API 直接写进养成规则。

1. **规则层**：继续使用 `farm-state.js`、`world-state.js`。所有购买、收获、喂养、狩猎冷却和存档迁移在此层保持确定性。客户端只能发出语义动作，不能自报余额或资产归属。
2. **平台层**：新增 `PlatformSession`、`SaveRepository`、`InputAdapter`、`AudioAdapter` 和 `LifecycleAdapter`。平台层封装微信登录、前后台切换、触控、存储和音频差异，网页端提供兼容实现供回归测试。
3. **渲染层**：新增 `WorldRenderer` 入口，负责庭院、山谷、猎场的 Canvas/WebGL 场景加载、卸载、镜头、碰撞代理、动画和资源回收。渲染回调不能直接修改钱包或家园归属。
4. **画布 UI 层**：把主菜单、地图入口、动物照料、背包、安币余额、狩猎提示和错误反馈整理成画布状态机。必要的输入框、授权按钮可使用微信原生控件，但业务状态以统一 UI 状态驱动。

建议接口（名称可在实现时调整，但语义保持稳定）：

```text
PlatformSession.startLogin() -> { playerId, sessionToken, expiresAt }
PlatformSession.getSession() -> { playerId?, guest, expiresAt? }
SaveRepository.load() -> { state, revision, source }
SaveRepository.save(state, expectedRevision) -> { ok, revision, conflict? }
WorldRenderer.loadRegion(regionId)
WorldRenderer.unloadRegion(regionId)
WorldRenderer.setPlayerState(playerState)
InputAdapter.onCommand(command)
LifecycleAdapter.onHide()/onShow()
```

`startLogin()` 内部先取得微信登录 code，再发送到服务端验证并映射为安和里 `playerId`；客户端拿到 code 不等于登录成功。平台密钥和 session key 留在服务端。登录失败时可允许游客体验，但必须明确当前为本机进度，不能把失败伪装成已登录。

云存档写入携带 `expectedRevision`，由服务端按玩家身份验证归属并返回新版本。离线本地快照标为“待同步”，不是云端成功。冲突时保留两份恢复候选并提示选择，不把两份余额相加。旧网页本机存档不自动提升为微信账号资产，导入需要一次性标记和明确确认；即便免费版也不靠重复导入重新发放资源。

## 迁移任务与责任

### 第 0 阶段：基线冻结（0.5 天）

- Codex：标记网页回归基线提交，确认日历文件不变，冻结免费版数值快照。
- Codex：把经济常量集中到配置模块，默认值与现有 `farm-state.js` 完全一致；本轮不改数值。
- Muse：从最新基线创建微信画面分支，列出现有资源的尺寸、纹理、动画和许可证。
- 产物：基线提交号、资源清单、免费版范围表、回滚点。

### 第 1 阶段：微信壳与画布入口（2 天）

- Codex：建立独立小游戏入口和平台适配目录，提供网页 mock 实现；补充构建脚本和环境变量说明。
- Codex：实现生命周期事件、错误边界、加载页和版本信息；前后台切换时暂停计时和渲染循环。
- Muse：完成首屏画布布局、触控热区、加载反馈和窄屏适配；保持安和里视觉语言。
- 验收：目标开发工具能启动、显示非空 Canvas、触控命中，切后台再回来不白屏、不重复扣除资源。
- 技术闸口：先用当前 Three.js 版本验证图形上下文、纹理/字体、帧循环、音频和生命周期；开发工具通过后仍需真机通过。若有阻断，再评估维护中的小游戏渲染适配方案；不直接用旧小程序适配包降级整个网页引擎。

### 第 2 阶段：庭院、山谷、猎场最小场景（4 天）

- Codex：提供区域 ID、入口/出口、碰撞边界和动作命令契约；保证庭院、山谷、猎场状态切换不丢存档。
- Muse：迁移瑞丽总佛寺外围、江畔家园和第一段猎场；完成移动、动物选中、喂食、收获、狩猎瞄准反馈。
- Muse：实现低端设备资源降级、对象释放和必要的 LOD；提交同一视角的帧时、内存和加载记录。
- 验收：步行进入三个场景，完成一轮养成和一次狩猎；场景卸载后无重复监听器、纹理和动物实例累积。

### 第 3 阶段：微信登录、云存档与恢复（4 天）

- Codex：定义 `PlatformSession` 和 `SaveRepository` 的版本、冲突、失败码及游客回退策略；实现服务端微信 code 校验与玩家映射，提供账号退出和撤回授权后的处理方式。
- Codex：实现持久化云存档、本地快照适配和写入节流；切后台、主动退出、网络失败时保留最后确认状态与待同步标记。服务重启后不能丢档。
- Codex：给现有庭院多人客户端增加微信网络适配，并把登录会话与临时庭院房间分开；保持房间容量、邀茶确认和断线重连行为。
- Muse：实现登录入口、游客提示、昵称、保存中/成功/失败反馈和恢复确认画面。
- 验收：首次登录、游客体验、切后台、杀进程重开、跨设备恢复、写入失败、网络中断、云端版本冲突、服务重启和旧版本存档迁移均有可复现结果；错误提示不能显示成功。

### 第 4 阶段：免费经济与体验闭环（2 天）

- Codex：接入配置化经济常量，但默认值不变；确认土地、动物、种子、出售、每日补给和狩猎奖励均走同一规则层。
- Muse：完成安币余额、产物出售、购买确认和余额不足提示；不显示充值入口或可点击的支付假流程。
- Codex：接入最小数据埋点：会话开始/结束、场景进入、首次买地/领养/收获、保存失败、登录失败和异常退出恢复。事件只记必要的匿名或假名标识，不收集手机号、通讯录、精确位置或聊天内容。
- 双方：用真实事件查看首次完整循环时长、留存、各场景停留、保存成功率和崩溃情况；不把在线人数或收入假造为真实运营数据。
- 验收：新玩家能从初始安币走完“买地/动物 - 照料 - 收获 - 出售”闭环；重复点击不会重复扣币或重复发放。

### 第 5 阶段：真机回归与发布前检查（3 天）

- Codex：跑规则、迁移、构建和静态敏感信息检查；整理已知限制和回滚包。
- Muse：在至少一台低端和一台主流设备测试触控、画面、音效、后台恢复、发热和帧率。
- 双方：核对资源许可证、隐私提示、登录授权说明和崩溃日志；只生成测试包，不提交正式发布。

按并行推进估算，免费版首轮约 12 至 15 个工作日，不含平台审核等待与账号材料补齐时间。第 1 阶段结束后按真机验证结果重新估时；若微信 Three.js 适配或资源压缩出现兼容问题，先交付庭院单场景技术验证，完整首发范围仍按庭院、山谷、猎场、登录与云存档验收。

## 后续接口预留

免费版完成后再评估：更强的权威家园与资产校验、联机区域、好友互访、玩家交易、经济账本和支付适配。第二期互访与交易必须独立立项并由服务端验证归属、容量、交易和并发；不能直接互信客户端存档。支付开关必须默认关闭；即使未来加入充值，也不能由客户端决定订单金额、支付结果、余额或资产发放。本轮不创建支付页面、不接商城数据库、不提交虚拟支付审核。

Muse 提出的“NPC 每日收购 80 安币”与“动物盛产期 45 天”属于第三期经济模拟假设，尚未完成本仓库复跑和真实玩家验证，不是已采用规则，也不把模拟结果表述为经济已跑通。第三期需先确定免费期余额过渡、旧玩家补偿、内容消耗面和服务端判定，再按真实行为数据校准。

## 本轮审查依据

本计划依据当前仓库基线 `7312879` 的代码审查：`src/main.jsx` 使用 React DOM 启动；`src/Courtyard.jsx` 直接读取 `localStorage` 并管理 DOM 弹窗；`src/scene.js` 创建 Canvas 纹理；`src/farm-state.js` 和 `src/world-state.js` 为可复用规则模块；`service/server.mjs` 为内存庭院服务，尚无持久化玩家和云存档端点。
