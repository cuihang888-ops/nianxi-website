# 瑞丽全域大地图布局（2026-11-15）

收件人：Codex。配套数据模块：`wechat/vendor/ruili-region.cjs`（本文所有数值从该模块抄录，两边以模块为准；模块测试 `tests/ruili-region.test.mjs`，并与村落契约模块 `shared-village.cjs` 做交叉一致性断言）。
基线：`muse/shared-world-scenes` @ `1ced5d0`（村落布局 v2 定稿之上）。用户要求原话：「一样做瑞丽市全地图，能做多大做多大，大概位置的标志性的东西还是要有，瑞丽江、瑞丽大道、姐告、弄莫湖等」；同日追加硬要求：「一定要全方位的大，我们需要吸引同时在线几千人能玩能在的，这些人要安家，要有足够大的地方。」（容量账见 §7。）
本契约只定全域布局与坐标口径，不表示规划区已建成、已可玩；现状与规划在数据里逐项用 `status: built | planned` 区分（见各表）。

## 1. 范围与两层口径

全域坐标用**坝内坐标**（与现有瑞丽场景 `ruili-scene.cjs` 的 spec 同一套：右手系、Y 向上、北 −Z、东 +X，`yaw = atan2(dx, dz)`，游戏单位不宣传为现实测绘米）。现有锚点一律不挪位，总图只向外扩：

| 层 | 范围（坝内坐标） | 面积量级 | 含义 |
| --- | --- | --- | --- |
| 现状 `playableNow` | 椭圆 cx0/cz0、rx **250**、rz **205**（包围盒 x∈[−250,250]、z∈[−205,205]） | 500 × 410 | 现有瑞丽场景已覆盖、已可玩的范围，数值逐字抄自 `ruili-scene.cjs` 的 spec `bounds` |
| 总图 `masterPlan` | x∈[**−640, 680**]、z∈[**−480, 470**] | **1320 × 950** | 瑞丽全域总图规划范围：西到弄岛出境、东过畹町、南含姐告对岸片区、北抵南宛河入境谷口 |

模块字段：`REGION_BOUNDS = { playableNow, masterPlan }`。两层之外没有第三种口径：不在 playableNow 内的，一律是规划，不得在客户端呈现为已可玩。

## 6. 姐告对岸片区

- **过江点**：姐告道自集市 (0,6) 南下，经瑞丽渡口 (8, 152)——现有场景里江边泊着的竹筏就是这个渡口（built）；过江段 (12, 196) 为**姐告桥 · 古渡**（planned）：原始社会底色下是藤桥/古渡，不落现代桥面结构。玩家过江的动线是「走到渡口 → 竹筏/藤桥过江 → 姐告」，与村落小地图的「桥」要素对应。
- **对岸有什么**：片区中心 (16, 246)，内容按地方图设计稿的意象落位——**古渡 + 玉城早市**：一处临江的清晨集市氛围点与歇脚处，是南岸唯一的成规模人气点。边界写清：早市在本契约里只是**氛围与社交落位**，是否赋予交易功能、用哪套价格，等服务端目录与经济配置冻结；本契约**不预设第二套集市**，系统集市仍只有坝心一处 (0,6)。
- **片区范围**：总图南界 z=470 含整个对岸条带，但本轮只落位姐告片区本身；其余南岸在总图上是异域背景（看得见、暂不展开），不作可玩片区规划，也不在那边排村落基址（§7 的基址全在北岸与河谷）。

### 7.2 容量账（把数算清楚）

- **每村首期 8 块**：与村落契约的定稿排布同口径（30×32、带土巷与公共保留的一整排村格局），新村开村即按这个数起步，不用临时凑地。
- **每村上限 32–48 块的估算依据**：单块地 30×32 = 960；连上土巷、土径、村心公共保留与地形损耗，平均每户实际占地约 1700–2200 游戏单位²；单个基址周边的可安家地带约 7–10 万单位² → 约 32–48 户。逐村按地形给值（坝田最开阔 48、河谷最窄 32，见上表），不是一刀切。上限是**总图估算**：每一轮实际扩村排布仍须按村落契约的判定（压路 ≥ 8、压水、保留区）逐块校验后才生效；其中 0001 湖畔村现行详细契约固定的是首期 8 块，其 40 上限要等后续排布轮次逐块落位。
- **瑞丽一区合计**：11 处基址，首期 **88 户**，全图扩满 **420 户**（模块 `REGION_CAPACITY` 由基址表求和，文档与测试都用这个数，不另算一份）。
- **五区合计推算口径**：其余四区（芒市、陇川、盈江、梁河）尚未做全域图，按与瑞丽相同的布村标准推算——每区 10–12 处基址、每村上限约 40 → 每区约 400–480 户，**五区合计约 2000–2400 户**；若各区基址加密到 15 处量级，总量可达 **约 3000 户量级**。这是量级推算，不是承诺数：每区的实际数要等各自的全域图按本地形落位后重算。
- **在线承载口径（与交接文档一致，不另立说法）**：几千人同时在线靠**多村落 + 邻近订阅 + 在线频道**承载——玩家分散在几十个村落与公共区里，客户端只绘制邻近范围的人；**地权与频道分离**：家园占地是持久目录数据（主人不在线，地和房子也在），频道只是临时在线分片，换频道不换地。**不承诺几千人同屏**，也不伪造在线人数。村满了由服务端按本表的预留基址开新村（新 `villageId`），**老村坐标与已分配地块永不重排**——先住下的人，家永远在原地。

## 9. 打折、纠偏与待确认（如实记录）

- **莫里方位纠偏**：现有场景 `ruili-scene.cjs` 把一处瀑布景放在西北 (−158, −118) 并在注释里称「莫里瀑布（西北山里）」；但真实地理上莫里在瑞丽城东，2026-11-13 地方图设计稿也把莫里瀑布、莫里温泉、莫里河画在东线。总图从真实地理与设计稿：莫里瀑布落东侧 (430, −260)（planned，东线古道尽头）。现有场景西北那处瀑布景本轮**不动**，在总图里如实另标为「雨林瀑布（现状景）」（built），不冒充莫里；将来场景实现轮次要不要把它改名/改作无名雨林瀑布，等那一轮再定。
- **总图大 ≠ 现在就能玩那么大**：masterPlan 是规划范围，其内 planned 的地形、水系渲染、碰撞、植被都还不存在；当前唯一可玩范围仍是 playableNow 椭圆。1320×950 是「能做多大做多大」的总图尺度承诺（落位与目录先行），不是现状描述。
- **姐告只落一片**：南岸条带只落位姐告片区，其余对岸不规划、不排基址（§6）；姐告道过江段与藤桥均为 planned，现状过江只有渡口竹筏这个点是 built 的。
- **村落上限是估算**：§7 的 32–48/村与五区 2000–3000 户是按占地口径的量级推算；逐村扩容要在后续排布轮次逐块过校验，校验不过就降上限，不硬塞。
- 待 Codex 冻结项集中在 §8 表格：世界/村落目录形状、villageId 分配、预留基址启用顺序、plots 编码与价格单位（沿村落契约）、姐告早市的交易功能口径。
