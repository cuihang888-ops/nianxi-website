## ② 三项重点逐项发现

### (a) 路标 / 地标是否清楚

**先说好的**：出生点（截图 `01-desktop-start-yard.png`）构图本身就是一张地图——湖在左上、石板路在脚下分叉（一条沿湖、一条下行接大道）、羊圈围栏和三只羊在右侧、田地要走的空地在中间。不靠任何 UI，湖和羊圈「在哪」第一眼成立。集市本体（截图 `16-desktop-market-longwait.png`）摊位、会馆、房舍密度高，到达后不需要再找路。

**问题按严重程度**：

- **A1（文案误导，最刺眼）去湖边、去羊圈的出发提示都写「回小院」。** `app.js:509` `goToPublicPlace()` 的提示只分两种：目标是集市中心写「沿瑞丽大道前往集市。」，其余一律写「沿瑞丽大道回小院。」。实测两次坐实：点「去湖边」（`app.js:521`）后全程提示「沿瑞丽大道回小院。」（截图 `06-desktop-lake-arrived.png` 左下角，抵达湖边、拋竿按钮已出现时仍是这句）；点「去羊圈」（`app.js:525`，目标是圈门 `gate={x:3.75,z:4.6}`）同样显示这句（补测日志 PEN poll 0–3 全程如此）。玩家会以为点错了按钮。
- **A2 场景内只有一块「地名牌」，没有任何「指路牌」。** 全场唯一的文字路牌是大道牌：`avenue-marker.js:3` 位置 `(-2.75, 10.1)`，牌面 2.20×0.57 m（`avenue-marker.js:4-6`），只写「瑞丽大道」四字，不指向任何目的地。在出生点默认视角里它只有约 90 px 宽（截图 `02-desktop-canvas-start.png`），且牌面只在正面可读——拖动转镜头到背面后牌面呈镜像、夜里几乎读不出（截图 `05-desktop-menu-routes.png` 下方）。集市会馆有「瑞丽集市」牌（`ruili-street-model.js:150-154`），但那是到了才看得见的门牌，不是路牌。湖边、羊圈、田地三个目的地在场景里没有任何一块带字或带箭头的牌子。
- **A3 真正的「路线入口」藏在侧栏折叠区里。** 「去湖边 / 去羊圈」按钮在 `index.html:163-167` 的 `<details class="heritage">`（摘要文字是「去处与人物」）内，默认折叠。桌面首屏实测可见按钮只有「春 / 白天 / 去集市 / 选地」四个——评审说明里写的「用『菜单』能找到去湖边和羊圈的路线」，但界面里没有任何叫「菜单」的元素，玩家要先猜到「去处与人物」里藏着路线。小屏更甚：该折叠区在画布和命令栏下方，需下滑才够得到（截图 `12-mobile-390-start.png`）。
- **A4 「田地」根本不是一个可前往的目的地。** 生存新档 `plots=[]`（首个 snapshot `context.plotId=null`），田地必须自己先「选地」在院边空地选址、再去集市买下（买地按钮要求处于集市交易态，见 `app.js` `buy-plot` 处理）。所以「从小院走到田地」这条评审动线对新玩家实际是「先造一块田」；场景里也没有任何预设田垄/田间地标可供辨认（截图 `01` 里院边全是草甸）。出生提示「点『选地』在附近的空地开一块田」有交代，但玩家若按「找田地」的预期进场，会找不到。
- **A5 长途自动步行没有任何进度感，且「进入集市」与「到达集市」判定不一致。** 集市中心在 `(34, 8.25)`（`ruili-street.js:6`），从湖边出发全程约 46+ 单位。自动步行期间唯一的反馈是按钮变「取消前往」，没有距离、没有沿途地名变化（左上角地点牌只在踏上大道/进入集市场时才亮，`app.js` `draw()` 中 `locationLabel` 逻辑）。更别扭的是范围判定：`inMarket()` 是广场矩形 `x∈[27.5,40.5], z∈[3.6,10.55]`（`ruili-street.js:35-38`），补测中玩家 `x=27.53` 时 snapshot 已报 `market.near=true`、画面左上角已显示「瑞丽集市」，但自动步行要走到距中心 <0.38 才结束（`app.js` `move()` 中 publicRoute 到达判定），截图 `16-desktop-market-longwait.png` 里人已站在广场中，左下提示仍是「沿瑞丽大道前往集市。」、按钮仍是「取消前往」、集市面板未打开——「到了」和「还没到」同时成立约数秒（无头时更久）。

### (b) 抛竿、施肥、抚摸、喂养的动作反馈

**总判：四个动作里，抚摸反馈最完整，抛竿次之，施肥和喂养在 3D 里近乎「无反馈」。且本离线包四个动作全程无声**——`demos/anheli-module-yard/*.js` 全目录检索 `Audio` / `AudioContext` 为 0 处（仓库 `src/audio.js` 的音频模块没有被 yard 试玩引用，`browser.js` 只 import `app.js`）。

- **B1 抛竿：流程与漂相都对，但主角看不见。** 实测完整走通：到湖边（距钓点 <2.3 时「抛竿」出现）→ 点击后若距钓点 >0.54 先自动沿碎石路走到钓点再抛（`app.js:447-459`，`fishingRoute`/`castLine`）→ 提示「鱼漂落水了，等它动一动。」→ 鱼漂+鱼线+扩散涟漪圈出现（`view3d.js:53-99` 的 `createFishingVisual`：涟漪周期扩散、透明度衰减）→ 咬钩延迟 3–6 秒随机（`fishing.js:41`；实测首轮询时剩 1,022 ms、下一轮询已咬钩）→ 咬钩时鱼漂抖动频率从 2 Hz 跳到 12 Hz、振幅 .012→.056（`view3d.js:89`）、涟漪变快变亮（`view3d.js:94-97`），人物右臂有持竿姿势（`figures.js:216`）→ 点「收竿」得「钓到一条草鱼，放进了鱼篓。」（截图 `07-desktop-fishing-waiting-or-bite.png`、`08-desktop-fishing-reeled.png`）。
  问题有二：①**构图丢人**——相机近湖时目标点被插值到湖心 `(-17.3, -4.3)`（`view3d.js:252-254` `byLake`），玩家和竿的根部被前景大树树冠完全挡住，截图 `06`、`07` 里只见鱼漂和半截鱼线悬在水面，钓鱼的人不在画面里（微信版已有的「树冠遮挡淡出」在 Web 版 `view3d.js` 里没有对应实现）；②**咬钩没有离散信号**——咬钩瞬间提示文字不变（仍是「鱼漂落水了，等它动一动。」），唯一的通知是下方按钮区悄悄换成「收竿」；不盯着鱼漂就会错过状态变化（好在咬钩不设超时，`fishing.js:53` `reel()` 只判 `now>=biteAt`，错过不惩罚，这点是对的）。
- **B2 施肥：规则对，画面零变化。** 规则层有测试背书（`livestock.js:421-432`：须先浇水、花 2 体力、生长时间系数 ×0.75，`economy-config.js` `cropFertilizer`；若施肥后即达成熟阈值，文案会说「已经可以收获」）。但表现层：`field-models.js:246-256` 的田块刷新只按 `cropStage()` 的阶段（empty/dry/growing/ready）换土色和苗模型，全目录检索 `fertilized` 在 `field-models.js`、`view3d.js`、`woodland.js` 中**零引用**——施肥前后田面、苗株看不出任何区别（除非恰好跨过成熟阈值跳阶段）；人物没有施肥姿势（`figures.js` 只有走/骑/持竿三种姿势），没有撒肥的粒子或动作，唯一反馈是侧栏一行文字。本轮未实玩走完施肥链（原因见 ④），此条为代码审查 + 单元测试结论。
- **B3 抚摸：反馈最全，但「第一次点击」时机别扭、爱心偏小。** 实测走通：羊圈内点「摸摸小羊」→ 小羊停步转向玩家、跳跃（`figures.js` lamb `animate()` 的 reaction：`hop` 最高 .135、头下压）、头顶升起粉色爱心（`view3d.js` flock 段：爱心在 `ground+1.37+passed*.35` 处上浮、1.55 秒内淡出，`animals.js:4` `REACTION_DURATION=1.55`）、名字牌亮起、提示「绵绵蹭了蹭你的手。」（截图 `10-desktop-pet-reaction.png`，爱心在白羊头顶清晰可辨）。两个小问题：①**动作出现偏晚且中间文案误导**——羊圈情境在玩家 `x≥2.7` 的大矩形内就触发（`app.js` `nearPen()`），但 `animals.interact()` 的实际触及距离是 2.35（`animals.js:3` `REACH`）；补测中玩家在 `(3.38, 4.53)`（已亮「摸摸小羊」、情境显示「羊圈」）点击，最近的羊在 `(6.25, 4.20)`、距约 2.9，点击后先回一句「走进羊圈，靠近小羊就能摸摸它。」（人明明已在圈门），随后自动走近约 1 秒才真正摸到（snapshot 先测到 `petAt=null`、截图时已完成抚摸）；②爱心在默认缩放下约 10 px（1440 宽截图），远看容易漏掉。人物同样没有伸手姿势。
- **B4 喂养：动画能力写好了，但没接线。** `livestock.js:317-350` `care()` 只改状态（`fedAt`、扣饲料/体力）并返回一行文字（如「已喂 2 只，用了 2 份饲料，约 65 秒后可收羊毛。」）。而牲畜模型其实预留了受抚/进食动作：`livestock-models.js:249-263` `animate(time, moving, stroke=0)` 里 `stroke` 会驱动低头（`head.rotation.x -= pet*.135`）和身体起伏——但全场唯一的调用处 `view3d.js:385` 是 `model.animate(time, mounted?player.walking:record.moving)`，**从不传第三个参数**，`fedAt` 也不映射任何视觉（不走向食槽、无饲料撒落、无进食低头）。结果：点「喂养/收取」后 3D 世界里什么都不发生，只有侧栏集市面板的文字和数字变。本轮未实玩喂养（新档无牲畜，见 ④），此条为代码审查 + 单元测试（喂养扣费/结算用例在 yard 17 项中通过）结论。

### (c) 摇杆与点地操作（重点为小屏）

**先说好的**：点地行走桌面与小屏都实测可用，`routeThroughYard()`（`yard-navigation.js`）的 BFS 寻路能绕围栏和墙，点到水面/障碍会给文字提示而不是傻走（`app.js:965-977` `walkTo()`）；摇杆是模拟量（推多远走多快，`browser.js:21-30` + `app.js` `setMovement()`），松手即停（实测松手后 snapshot `walking=false`），`blur`/`lostpointercapture` 都会释放摇杆（`browser.js:43-51`），摇杆生效时点地被忽略、防误触（`app.js:926`）；小屏无横向溢出（实测 `scrollWidth<=innerWidth`）。小屏首帧截图 `12-mobile-390-start.png`、`13-mobile-390-canvas.png`。

**问题**：

- **C1 双指转镜头在 Web 试玩里不存在（代码审查，未实测部分见 ④）。** `app.js:982` `pointerDown` 是 `if(gesture||event.button!==0)return;`——只追踪第一个指针，第二个指针按下直接被丢弃；`browser.js:15-18` 也只注册了单手势的 down/move/up，全 demo 没有任何捏合距离计算。所谓「双指转镜头」在这一版实际是**单指拖动转镜头**；双指操作时第二根手指完全无响应，既不转也不缩放。若评审预期里双指应有效，这是功能缺失而非手感问题。
- **C2 单指拖动的灵敏度与误触阈值偏激进。** 拖动判定阈值只有 5 px（`app.js:989`），超过即算拖动：小屏上手指点地时稍有滑动（>5 px 很常见）就会变成转镜头而不是走路，且点地走路只在 `pointerUp` 且未拖动时才触发（`app.js:994-998`），误触后没有任何提示说「刚才那下被当成了转镜头」。转镜头本身偏快：`view3d.js:504` `orbit()` 为 `yaw -= dx*.007`，实测横拖 180 px → yaw 从 0.40 变到 −0.86（转了约 72°）、pitch 0.60→0.76，一次随手拖动就大幅换向（对比截图 `03`→`04`）。另一个连带伤害：拖动开始即 `clearPath()`（`app.js:990`），**自动步行去集市途中无意一碰画面，长途路线被静默取消**，没有「路线已取消」的提示，玩家只会发现人停了。
- **C3 点地没有落点标记。** 全 demo 检索不到任何目的地标记/涟漪/路径预览（唯一的 `marker` 是大道牌）。点下去之后唯一的确认是人物开始走——若点的位置被判定为羊/马（`view3d.js` `hitSheep` 半径 ≥15–16 px、`hitHorse` 同理），点击会变成「走向小羊」或骑马，而不是走到该点；在羊圈边点地很容易点到羊（羊圈紧邻出生点东侧）。点远处时也无法预知路线会绕哪边。
- **C4 摇杆遮挡与位置。** 摇杆仅在粗指针设备显示（`index.html:87-89`），84×84 px、定位 `bottom:48px; left:14px`。390×844 实测：摇杆盒 `(29,364)–(113,448)`，画布盒 `(15,100)–(375,496)`——摇杆占画布宽度约 23%、高度约 21%，正压在默认构图的左下角（湖滨小路与大道牌所在区域，截图 `12`、`13` 中摇杆圆盘盖住了左下路面一角）。与底部消息条的关系是对的：消息条顶边实测 448.6 px、摇杆底边 448.2 px，恰好相邻不重叠。但摇杆是 `aria-hidden="true"` 的纯视觉件（`index.html:141`），且它的触摸区与画布点地区域相邻，推杆时手指滑出圆盘边缘会落到画布上触发拖动转镜头（摇杆有 `setPointerCapture`，`browser.js:39`，同一指针不会串扰；此条为相邻区域误触风险提示，未在无头环境复现）。
- **C5 情境按钮出现时机普遍「早半步」。** 除 B3 的羊圈例外，湖边同理：「抛竿」在距钓点 <2.3 时就出现（实测 LAKE poll 5 人还在路上按钮已亮），点击后先进入 `approach` 再自动走完——按钮文案会变「走到岸边」（`app.js` `updateFishingControls()`），算有交代，但玩家第一眼会以为站着就能抛。集市交易类按钮则相反，要 `openMarket && inMarket` 同时成立（`trading()`）才出现，配合 A5 的到达判定，玩家进广场后还要多走一段才见得到买地/买种按钮。

## ③ 优先改动（恰好三条）

### 优先 1：把「指路」做成系统——改错文案 + 分叉口指路牌 + 路线按钮出折叠区〔对应 (a) / A1、A2、A3〕

改动内容：① `goToPublicPlace()` 按目标分别给提示（去湖边→「沿碎石路去湖边。」，去羊圈→「去羊圈看看小羊。」，回小院保留现文案）；② 在出生点南侧石板路分叉口（大道牌旁）加一块双面可读的指路牌，写清三个方向：湖边 ←、羊圈 ↑、瑞丽大道/集市 →（牌面双面同纹理、勿镜像）；③ 「去湖边 / 去羊圈」从侧栏折叠区提到主命令栏（与「去集市」并列），折叠区可留作次级入口。
复现步骤：新档 `?survival=1` 进场 → 展开「去处与人物」→ 点「去湖边」，读左下提示（现为「沿瑞丽大道回小院。」）；再点「去羊圈」，同样误报；站在出生点看大道牌，读不到任何目的地信息。
可验收效果：三条路线出发提示各说各的目的地、无一再出现「回小院」误报；不打开任何面板，站在出生点分叉口能从指路牌读出去湖边/羊圈/集市三个方向（正反两面绕行一周文字都正读）；主命令栏直接可见「去湖边」「去羊圈」按钮，小屏首屏（390×844 不滚动）即可点到。

### 优先 2：让动作反馈「看得见」——湖边构图保人、施肥留痕、喂养接通低头动画〔对应 (b) / B1、B2、B4〕

改动内容：① 湖边相机目标改为玩家与鱼漂的中点（或给湖畔前景树冠加遮挡淡出，微信版已有同类实现可移植），保证抛竿时人物、鱼竿、鱼漂同框；咬钩瞬间补一个离散信号（提示文字变「鱼上钩了！」或鱼漂下沉+一圈急涟漪，现 `bite` 抖动保留）；② 施肥后田块要有可见变化（如土色加深一档或苗株描一圈嫩绿，`field-models` 刷新键加入 `fertilized`）；③ 把 `livestock-models` 已写好的 `stroke` 参数接上：喂养成功后让被喂动物播放一次低头进食（`view3d.js:385` 调用处按 `fedAt` 新鲜度传 `stroke`），顺带给抛竿/喂养/施肥共用一记轻音效（Web Audio 合成即可，本包目前全无声）。
复现步骤：湖边抛竿，看画面（现截图 `07`：只有鱼漂、钓鱼的人被树冠挡住）；种一茬已浇水的作物点「施肥」，对比田面前后截图（现无区别）；在集市买一只羊和饲料、回羊圈点「喂养/收取」，盯着羊看（现只有侧栏文字变化，羊无任何动作）。
可验收效果：两个钓点抛竿截图中人物+整根鱼竿+鱼漂同时可见，咬钩 1 秒内出现文字或下沉信号；施肥前后同机位截图能一眼指出田块差异；喂养后被喂的羊在 1 秒内低头进食一次，侧栏文案与动作同时发生。

### 优先 3：小屏操作补三件小事——点地落点标记、双指/拖动不再误杀、自动步行防误触取消〔对应 (c) / C1、C2、C3〕

改动内容：① 点地成功时在落点放一个短暂涟漪/光圈标记（点到羊/马时标记落在动物身上并给不同颜色），让玩家确认「点中了哪」；② 支持双指手势：第二个指针按下时进入双指模式（双指同向拖动转镜头或捏合调俯角），单指拖动阈值从 5 px 提到约 10 px，减少点地被吞；③ 拖动转镜头不再静默取消自动步行路线——要么拖动只转镜头不清路线，要么取消时回一句「已取消前往集市」。
复现步骤：小屏（390×844）点画布远处地面（现无任何落点提示，只能看人动没动）；双指同时拖动（现第二指无任何响应）；点「去集市」开始自动步行后轻拖一下画面（现路线被取消且无提示，人停在半路）；手指点地时滑动约 6 px 松手（现被判拖动、不走路）。
可验收效果：每次有效点地落点处出现可见标记（含点到羊/马的情形）；双指拖动能转镜头且不触发点地行走；自动步行中拖动转镜头后，或路线继续、或出现明确取消提示，二者必居其一；6 px 抖动的点按仍按点地处理、人物开始移动。

## ④ 未实测项（如实清单）

1. **双指手势未做真机/真双点实测**：无头 Playwright 的 touchscreen 在本环境只支持单点 tap，无法模拟双指同时触摸。C1 的结论来自代码审查（`app.js:982` 单手势守卫 + 全目录无捏合逻辑），未在真机上复验「第二指被忽略」的手感细节。
2. **施肥未实玩走完**：完整链为 选地 → 去集市（交易态下）买地 → 买种子 → 回院 → 走到田边播种 → 浇水 → 进入 growing 阶段才出现「施肥」。无头环境自动步行去集市单程约 90 秒（墙钟）才进入 `near`，且游戏内一日仅 240 秒（`yard-clock.js:4`）、昼夜光照在评审中途多次翻转，整链未在单轮内走完。B2 以单元测试（施肥用例在 yard 17/17 中通过）+ 代码审查（`fertilized` 在渲染层零引用）为据。
3. **喂养（牲畜 `care`）未实玩**：生存新档无牲畜、无饲料，需先完成集市购买再回羊圈，同样受长链限制。B4 以单元测试（喂养扣费/产物结算用例通过）+ 代码审查（`view3d.js:385` 未传 `stroke` 参数）为据。注意：羊圈里三只「院羊」的抚摸已实测（B3），与牲畜喂养是两套系统，不要混为一谈。
4. **微信小游戏版未测**：本轮只测 Web 离线试玩；`node scripts/build-wechat-yard.mjs` 未运行，微信版的摇杆、双指与树冠遮挡淡出（其测试中有 camera-occlusion 用例且通过）不在本报告结论范围内——B1 的遮挡问题专指 Web 版 `view3d.js`。
5. **真机性能与手感未测**：所有时长均为 SwiftShader 无头墙钟时间；真机帧率、摇杆跟手度、拖动转镜头的实际手感需真机复验。报告中引用的速度/距离均为 snapshot 坐标与代码参数。
6. **音效「无声」为代码审查结论**：无头环境本身无法验证扬声器输出；结论依据是 yard demo 源码全目录无任何音频 API 调用。若构建产物在打包时另行注入音频（本次构建的 `play.html` 内检索同样无 `AudioContext`），此条不成立——已核，构建产物内亦无。
7. **非重点动线未展开**：骑马/下马、买房与宅院交易、卖鱼/卖收成结算、吃饭回体力等只做了按钮可见性层面的旁证，未逐项实玩；集市本轮到达了广场并确认交易前置条件（A5），但未在集市内完成一笔实际买卖。
